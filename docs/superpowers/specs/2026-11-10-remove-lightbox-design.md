# 移除共享灯箱 + 三处点击缺陷修复 — 设计

- 日期：2026-11-10
- 状态：**已实现**（验证结果见同日期 plan）
- 涉及页面：`/`（首页）、`/explore`（搜索）、`/gallery`（图库）、`/detail/<pid>`（详情）、`/settings`（设置）

## 背景

共享灯箱 `static/lightbox.js` 于 2026-08-26 前端重做时引入，后来收窄为「首页 / 搜索 / 图库」三页卡片点击弹预览。实际使用中不好用，用户要求整体删除。

它的成本不止"多余一次点击才看到详情"：

- 行为按页面分叉：图库是**图片区**开灯箱、**信息区**跳详情；搜索/首页是整卡开灯箱。同一手势在不同页面结果不同。
- 灯箱内页源探测另起一条链路（`/api/detail/<pid>` → `local_urls` / `medium_urls`），与详情页的候选链重复。
- 预览卡（搜索中未落库）在灯箱里只能拿到 250px 缩略图，于是又保留一条"预览卡例外"分支。

## 需求

1. 删除全部灯箱相关代码（脚本、模板引用、样式、接入点）。
2. 卡片点击统一为「跳详情页」，不保留任何弹层预览。
3. 同时修掉三处已确认的点击缺陷：
   - 详情页画师名链接指向 `/?type=user&query=<uid>`，而 `/` 是首页、不读 URL 参数 → 点了只回首页，不搜索。
   - 搜索页卡片标签上的 `×` 调用 `addBlockedTag`，但该函数只定义在设置页脚本里 → 抛 `ReferenceError`，无提示、不屏蔽。
   - 图库卡片下载链接带内联 `onclick="event.stopPropagation()"`，被 CSP `script-src 'self'` 拦掉，是死代码。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 首页 / 搜索 / 图库卡片点击一律 `location.href = /detail/<pid>` | 三处手势一致；详情页已有原图→中图→缩略图候选链，比灯箱的探测链路更完整 |
| D2 | 搜索页**预览卡**走同一入口，不再分支 | 详情页对未落库 pid 会回退到运行中任务的内存快照（`runtime.find_running_preview`）给出中图；灯箱那套 404 分支随组件一起消失 |
| D3 | 图库保留 `ctx=gallery&sort&page&pos` 导航上下文 | 「连续看下一作」的能力由详情页的「上一作/下一作」承接，不因删灯箱而丢失 |
| D4 | 删除 `static/lightbox.js`、三处 `<script>` 引用、`.lightbox-*` 样式、`prefers-reduced-motion` 里的相关选择器 | 不留下无引用的死资源 |
| D5 | `addBlockedTag` 提到 `app.js` 作为全站共享函数，设置页只负责刷新自己的列表 | 一份实现两处调用，避免再次出现"某页忘了定义" |
| D6 | 详情页画师名改指 `/explore?type=user&query=<uid>` | `/explore` 的 `page-index.js` 会读 `query`/`type` 并自动开搜 |
| D7 | 删掉图库下载链接的内联 `onclick`，保留卡片 handler 里的 `closest('a')` 守卫 | CSP 下内联属性永不执行；守卫才是真正拦冒泡的那道 |
| D8 | 「已下载」态的下载入口统一为**真链接** `<a href="/download_file/<pid>">下载原图</a>`（搜索/缓存/图库/下载管理/详情），删掉 `downloadFile()` 的 `window.open(..., '_blank')` 路径 | 四处文案与行为一致；真链接不吃 CSP、支持右键另存；详情页下载完成时就地换成 `<a>`，顺带修掉"只改 `onclick`、旧 `addEventListener` 仍在 → 点一下既跳文件页又重复 POST `/download/<pid>`" |

## 边界（明确不做）

- 不动「下载管理页缩略图不可点」（用户确认现状没问题）与缓存页卡片直接跳详情（删灯箱后与其他列表已一致）。
- 不改 `docs/superpowers/` 下的历史 spec/plan（它们是当时决策的记录），也不动 `opendesign/mockups/` 设计稿。
- 不新增替代交互（没有"点击放大"、没有弹层、没有网格内翻页）。

## 取舍

失去「留在列表里快速看图、看完继续逛」的路径，多一次页面跳转；换来三页手势一致、少一个组件与一条页源探测链路。图库场景的"连续浏览"由 D3 承接，损失主要在搜索页（原来可以灯箱连翻整页结果）。
