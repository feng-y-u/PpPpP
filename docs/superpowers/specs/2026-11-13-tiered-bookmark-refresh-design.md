# 收藏数分级刷新设计（2026-11-13）

## 背景

旧刷新逻辑对所有预取作品统一“入库满 1 天拉一次详情”，之后永久退出；首页候选并不比普通缓存更早刷新，且已下载作品也会白耗详情请求。目标是让首页候选更保鲜、普通/老作品按更低频率维护，同时不增加 Pixiv 限流风险。

## 决策

- **三档间隔（按最后已知收藏数时间计算）**
  - 首页候选：2 天（需求 1～3 天的中间值）。
  - 普通预取缓存：7 天。
  - 老作品：上传超过 30 天：30 天。
- **首页候选**：`prefetch_source=1`、未下载/下载中、有原图、收藏数 >0，且（7 天内有上传时间 或 收藏数 >500）。覆盖首页第一屏与 7 天回退窗口、随机池。
- **已下载排除**：`download_status in ('done','downloading')` 或 `local_paths` 非空的作品不参与刷新；不查 `DownloadLog` 历史（按用户确认）。
- **列表计数优先**：`_process_items` 在搜索/预取列表命中已有记录时用列表 `bookmarkCount` 更新；刷新候选按 `bookmark_updated_at` 判断是否到期，刚被列表回填过的作品不会再拉详情。
- **调度**：SQL 按档位、最后更新时间排序；每轮仍受 `PREFETCH_REFRESH_BATCH=300` 限制，详情走现有 `_fill_limiter`（20 条/分钟），不提高并发或速率。
- **失败退避**：保留 `refresh_failed_at` 24 小时退避；连续全局失败 3 条中止本轮；失败超过 14 天把最后更新时间推到当前，按下一档周期重试（不再永久退出）。
- **字段语义**：`prefetch_refresh_at` 改为“最近一次刷新完成时间”；`reset_prefetch_refresh` 同时清空 `bookmark_updated_at`，保证手动重置立即生效。

## 非目标

- 不新增数据库列或迁移。
- 不刷新 `prefetch_source=0` 的手搜/下载记录（避免扩大后台请求范围）。
- 不改 Pixiv API 端点、不提高令牌桶速率。

## 验证

- 分级优先级/到期重刷、已下载跳过、列表计数回填、失败退避与 14 天兜底均有回归用例。
- 全量：`488 passed / 2 skipped / 0 failed`（Python 3.13.13）。
