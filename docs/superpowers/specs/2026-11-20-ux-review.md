# 全站 UX/UI 审查与体验优化（2026-11-20）

对象：PpPpP（Pixiv Viewer + X 抓图）。范围：7 个页面 + 详情页 + 看图页，桌面 1440×900
与移动 390×844 两个视口，全部以真实浏览器（Chrome CDP）打开、操作、截图取证，
不是仅读代码。

## 一、取证方法

1. 逐页导航 → `Page.captureScreenshot` 截图 + DOM 度量（横向溢出、容器宽度、卡片数、
   空态可见性、破图数、body 高度）。
2. 真实操作：输入标签搜索、图库勾选批量删除、X 页下载、缓存页切标签、设置页保存、
   移动端展开导航抽屉。
3. 对照后端数据判断"页面空白"是数据问题还是渲染问题（例如缓存页 190 条记录却空白，
   最终定位为前端初始化漏调 `browseCache()`）。
4. 对判决为 bug 的现象，先抓真实上游响应确认字段形状（X 作者名为空 → 抓包发现
   `user_results.result` 已无 `legacy`，name/screen_name 迁到 `core`）。

## 二、问题清单（按严重度）

| # | 位置 | 表现 | 影响 | 级别 | 处置 |
|---|---|---|---|---|---|
| 1 | X 卡片 | 每张卡作者都是孤零零一个 `@` | 无法辨认画师；H1「同作者」去重因映射键为空永不触发 | P0 | 已修：`_author_of()` 同时读 `core`/`legacy`；入库时补写历史空作者 |
| 2 | 缓存页 | 顶部写"条数: 190"，网格全空、无任何提示 | 用户以为页面坏了 | P0 | 已修：进页自动浏览首个标签；空态区分"没抓过"与"缓存记录在但作品已不在库" |
| 3 | X 卡片 | 图片 `aspect-ratio:1/1` + `object-fit:cover` | 竖图/漫画被切掉上下，而这是作品浏览页 | P1 | 已修：按原始比例完整显示，`align-items:start` 不强行等高 |
| 4 | 缓存/首页/图库 | 缩略图取不到时 `<img>` 高度塌成 0 | 卡片变成"只有标题和按钮"的异类，与同屏卡片格格不入（缓存页 6/24 张） | P1 | 已修：失败重试后换成带"无预览"的占位块；空 `data-src` 直接占位 |
| 5 | 下载页 | 两个空状态各占 ~110px；「操作日志」标题白字白底几乎看不见 | 首屏浪费/信息不可读 | P1 | 已修：状态卡内空态紧凑化；标题改 `text-body` |
| 6 | 设置页 | 单列 3679px，保存按钮在最底部 | 改完一项不知道有没有存，常忘保存 | P1 | 已修：分区跳转条 + 保存栏贴底常驻 |
| 7 | 图库 | 孤儿作品显示空灰块 + 裸 pid 当标题 | 看起来像加载失败 | P1 | 已修：`is_orphan` 标记 + "仅本地文件"占位 + 诚实标题；操作按钮紧凑化 |
| 8 | X 页 | 筛选按钮写"含未下载"，语义反了 | 用户不知道点了会发生什么 | P1 | 已修：`全部作品` / `只看已下载` |
| 9 | 全站 | 6 处原生 `confirm()` | 与全站视觉断崖、无法换行排版、移动端阻塞 | P2 | 已修：`app.js` 的 `pvConfirm()`（Bootstrap modal，Promise 化） |
| 10 | 搜索页 | 首屏 700px 空白，每次重敲标签 | 重复劳动 | P2 | 已修：最近搜索 chips（localStorage，8 条） |
| 11 | 图库 | 每卡两个全宽按钮，红色删除与主操作同权重 | 视觉噪音，主次不分 | P2 | 已修：紧凑一行，下载为主、删除降级 |
| 12 | 首页/X | 加载期只有 spinner/无骨架 | 首屏短暂空白 | P3 | 未改（本地 <200ms，收益低） |

## 三、改动的文件

- `pixivviewer/x_client.py`：新增 `_author_of()`（core/legacy 双读）+ 调用点。
- `pixivviewer/background.py`：`_x_store_tweets` 对已存在但作者为空的行补写。
- `pixivviewer/helpers.py`：`_build_orphan_dicts` 增加 `is_orphan: True`。
- `pixivviewer/routes/xfeed.py`（上一轮）：`saved` 过滤、`/x/view`、`/api/x/image`。
- `pixivviewer/static/app.js`：`pvConfirm()`、`img-placeholder` 兜底（懒加载 + 错误重试两处）。
- `pixivviewer/static/page-cache.js`：初始化自动浏览、空态文案分两种原因。
- `pixivviewer/static/page-gallery.js`：孤儿卡渲染、操作区结构。
- `pixivviewer/static/page-index.js`：最近搜索（记录/渲染/点击即搜）。
- `pixivviewer/static/page-x.js`：作者行、紧凑操作区、筛选文案、`pvConfirm`。
- `pixivviewer/static/page-xview.js`、`page-settings.js`：`pvConfirm`。
- `pixivviewer/templates/x.html`：卡片图不裁切、作者/handle 排版、`align-items-start`。
- `pixivviewer/templates/gallery.html`：孤儿占位、操作区、`is-empty` 样式。
- `pixivviewer/templates/downloads.html`：状态卡内空态紧凑化、日志标题对比度。
- `pixivviewer/templates/settings.html`：跳转条 + 贴底保存栏 + 8 个分区锚点。
- `pixivviewer/templates/index.html`：最近搜索容器与样式。
- `pixivviewer/static/style.css`：`pvConfirm` 排版、`img-placeholder`、`img-failed` 最小高度。

## 四、验证

- 全量离线用例：**566 passed / 2 skipped / 0 failed**（新增 3 条：X 作者补写、
  非数字 tweet_id 拒收、孤儿行形状）。
- 真实浏览器复验：
  - X 页作者渲染为「風羽 @windwin69369561」；图片渲染比 `0.71` 与原始比一致（`cropped:false`）。
  - 缓存页进页 3s 内出 24 张卡；6 张无缩略图的卡在 ~3s 内变占位块，首卡高度稳定 527px（此前 134→527 跳两次）。
  - 设置页 8 个跳转锚点、保存栏在视口内（top 747，bodyH 3737）。
  - 下载页空态高度 56px（原 ~110px）、日志标题色 `rgb(33,37,41)`。
  - 图库：2 张孤儿卡标注"无记录（仅本地文件）"；批量选择浮条「已选 1 个 / 全选 / 删除 (1)」正常。
  - `pvConfirm`：标题/说明/按钮文字正确，取消后列表 24 张不变。
  - 移动端 6 个页面横向溢出均为 0；导航抽屉展开 7 个链接。

## 五、未覆盖 / 未解决

- 搜索/预取链路因本机无 Pixiv Cookie，只验证到"空态如实说明原因"这一层；
  真实结果页的卡片密度、翻页手感未在本机复验（离线用例覆盖了数据层）。
- 首页加载骨架（P3）未做。
- 图库缩略图仍为 1:1 裁切：为保持网格整齐刻意保留，完整图在详情页。
- X「画师关注模式」（只看指定画师的新作）属于产品功能，未在此次体验优化范围内。
